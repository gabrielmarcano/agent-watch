# Phase 5 — End-to-End Verification on the Pixel Watch 2 + Docs

> **Goal:** prove the whole chain works for each priority agent on the real device, then rewrite the README and ROADMAP for the new architecture. **This phase is the release gate.**

```
herdr → bridge (Mac, launchd) → relay (VPS, Cloudflare) → Pixel Watch 2 → relay → bridge → herdr → agent
```

|---|---|

## Setup

1. Relay deployed (3c). `curl https://relay.<domain>/v1/healthz` returns ok.
2. Bridge service running: `herdr plugin action invoke --plugin herdr-agent-watch status` shows `relay_connected: true` and `herdr_online: true`.
3. Watch paired, app installed from the **release** build (`./gradlew :app:installRelease`, or a signed APK), notifications allowed.
4. A **sandbox** workspace `aw-sandbox` with three panes in `/tmp/aw-sandbox`, one each running `claude`, `agy` and `opencode` in default permission mode (see the `capture-fixture` skill).
5. `tail -f ~/Library/Logs/agent-watch-bridge.log` in a separate pane.

## Checklist

Run the **whole** table once per agent (`claude`, `agy`, `opencode`), and record ✅/❌ plus notes in `docs/e2e-report.md`.

| # | Scenario | Steps | Expected |
|---|---|---|---|
| 1 | Live list | Open the app | The sandbox agents appear with the correct status and label within 2 s |
| 2 | Blocked shows the real ask | Ask the agent "run `ls -la`" | Watch vibrates (FCM). Notification title "<label> needs approval", body shows `ls -la`. In the app, the PromptCard shows the same command and options |
| 3 | **Deny is a real denial** | Tap **Deny** on the notification | The agent reports it was not allowed. **Then ask the same `ls -la` again: it must ask for permission again.** This proves Deny did not choose "don't ask again" |
| 4 | Allow from notification | Repeat 2, tap **Allow** on the notification | The agent runs `ls -la`. The notification turns into "Approved" and disappears |
| 5 | Allow from the app | Repeat 2, open the app, tap **Allow** in the PromptCard | Same as 4 |
| 6 | Stale tap is rejected | Repeat 2. Approve **on the Mac keyboard**, then tap Allow on the old watch notification | "Changed — open the app". **Nothing is typed** into the agent (check the pane) |
| 7 | Question menu (claude) | Ask for a multiple-choice question | PromptCard kind=question with one chip per option; choosing one selects it in the TUI |
| 8 | Unknown menu | Trigger a menu the parser does not know (any exotic dialog), or temporarily feed one in the sandbox | The watch shows the raw tail + Cancel only; Cancel dismisses it |
| 9 | Dictation to pinned agent | Open the agent in the app (pins it), go back, use the tile → dictate "say hello" | "To: <label>" shown; the agent receives "say hello" and starts working |
| 10 | Dictation while busy | Dictate while the agent is `working` | claude: accepted (queued). Others: "Agent is busy" (unless Phase 0 found they queue) |
| 11 | Done + history | Let a task finish | "<label> finished" notification; history item with the final answer; the reader renders markdown (source=transcript) |
| 12 | Screen fallback | Temporarily move the agent's transcript out of the way (sandbox only) or use an agent without a reader, then finish a task | History item appears with source=screen, rendered as plain text |
| 13 | Complication | Put the complication on the watch face; make an agent block | Shows the blocked count within 1 minute of opening the watch face |
| 14 | herdr stopped | Quit herdr with the Mac awake (`herdr server stop` — **ask the owner first**, it stops his sessions) | App shows "herdr stopped"; commands answer "herdr stopped" |
| 15 | Mac offline | Put the Mac to sleep (or `stop` the bridge) | App shows "Mac offline" within 1 minute; history is still readable |
| 16 | Recovery | Wake the Mac / restart the service | App returns to live state without re-pairing; no duplicate history items |
| 17 | Reboot survival | Reboot the Mac, log in, start herdr | Bridge is running without manual action (launchd) |
| 18 | Other agents | Start `codex` or any non-priority agent in the sandbox, if installed | It appears in the list; blocked menus with numbered options work via the generic adapter |

**Security spot checks** (once):
- `curl https://relay.<domain>/v1/agents` without a token → `401`.
- `curl "https://relay.<domain>/v1/agents?token=<device>"` → `401` (the query token is ignored).
- The relay journal (`journalctl -u agent-watch-relay`) contains no tokens and no prompt text.
- The bridge log contains no prompt text, only `text_len`.

## Docs to rewrite

**`README.md`** (English, for a new reader):
1. What it is (one paragraph) and a screenshot or GIF from the Pixel Watch 2.
2. The architecture diagram (from the plan §2).
3. Requirements:
   - herdr ≥ 0.9;
   - a VPS behind Cloudflare;
   - a Wear OS watch (primary) or an Apple Watch (best-effort).
4. Setup in order: relay (link to 3c) → bridge (`configure`, `start`, `pair`) → watch app (install, pair).
5. Supported agents: claude, agy, opencode first-class; others via the generic adapter.
6. Security model (short): outbound-only Mac, hashed device tokens, no raw keys.
7. Troubleshooting: `status` action, log paths, the "herdr stopped" vs "Mac offline" meaning.

**`ROADMAP.md`:**
- Move the achieved items to "Done".
- Remove Pushover/sidecar history that no longer applies.
- List the next ideas: Telegram notifier, phone companion, more adapters.
