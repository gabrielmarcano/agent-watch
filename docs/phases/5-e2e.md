# Phase 5 — End-to-End Verification on the Pixel Watch 2

> **Goal:** prove the whole chain works for each priority agent on the real device. **This phase is the release gate.** Why it is open and what the first run left unverified: [`docs/STATUS.md`](../STATUS.md).

```
herdr → bridge (host, launchd) → relay (VPS, TLS proxy) → Pixel Watch 2 → relay → bridge → herdr → agent
```

| | |
|---|---|
| **Touches** | this guide (the results), `docs/GUIDE.md` (Known Issues), `docs/STATUS.md`; on closing, a new `release-check` skill under `.agents/skills/` and `.agents/skills/wearos-deploy/SKILL.md` |
| **Needs the owner** | Yes: he wears the watch and taps, and runs the owner-only steps. The agent drives the sandbox, prepares each step and records the results. Rows marked **ask the owner first** wait for his OK; relay changes follow `AGENTS.md` §3 (do them and say so) |

---

## Setup

1. Relay deployed ([`deploy/relay/README.md`](../../deploy/relay/README.md)): `curl https://relay.<domain>/v1/healthz` returns `{"ok":true}`, and `agent-watch-relay version` on the box shows the deployed commit.
2. Bridge service running: `agent-watch-bridge status` shows the relay connected and herdr online.
3. Watch paired, the **release** build installed (`wearos-deploy` skill), notifications allowed.
4. A sandbox workspace `aw-sandbox` with three panes in `/tmp/aw-sandbox`, one each running `claude`, `agy` and `opencode` in default permission mode (`capture-fixture` skill, steps 1–2).
5. `tail -f ~/Library/Logs/agent-watch-bridge.log` in a separate pane.

## Checklist

Run every row once per agent (`claude`, `agy`, `opencode`) where it applies. **Record the results in these tables as you go:** add a column per agent with ✅, or ❌ and a short note, and commit after each block of rows.

Expectations name the error code or the state, not the watch's wording: the texts are in `wearos-app/app/src/main/java/com/gabriel/agentwatch/approval/CommandFeedback.kt` and `wearos-app/app/src/main/res/values/strings.xml`.

| 1 | Live list | Open the app | The sandbox agents appear with the correct status and label within 2 s |
| 2 | Blocked shows the real ask | Ask the agent "run `ls -la`" | The watch vibrates (FCM); the notification names the agent and shows `ls -la`; the agent screen shows the same command and options |

| 8 | Unknown menu | Trigger a menu the parser does not know (any exotic dialog), or temporarily feed one in the sandbox | The watch shows the screen tail and Cancel only; Cancel dismisses it |

| 20 | Cancel after the menu changed | With a prompt shown on the watch, make the agent show a different menu on the host (agy: bash prompt, then an edit prompt), then tap **Cancel/Deny** on the stale watch prompt | `stale_state` or `prompt_changed` (as in row 6); **no key is typed**; the watch then shows the new prompt |
| 21 | Dictation refused while a dialog is open | With an agent's permission dialog open, dictate to that agent | Refused (`agent_blocked`); nothing typed into the dialog |

| 23 | `resolved` push | Set `AW_PUSH_RESOLVED=1` and restart the relay (`deploy/relay/README.md`; say that you did); block an agent, answer it on the host | The watch's approval notification disappears within seconds |
| 24 | Live revoke | `sudo agent-watch-relay devices revoke <id>` with the relay running (**ask the owner first**) | The watch goes to pairing at once, saying the session expired, without a relay restart; re-pairing works |

| 26 | Silent stream | Make the stream go quiet without closing it (e.g. `docker pause` the proxy container for 60 s, then unpause; **ask the owner first**) | Within the silence timeout (`contracts.md` §2.3) the list dims and its notice says the relay link is down (connecting or relay offline); it recovers by itself after the unpause |
| 27 | Menu bar | `make bar`, open `bin/AgentWatchBar.app`; stop, start, restart and pair from its menu | The status circle and menu line match `macos-bar/README.md` § What the icon says; the Versions section shows the menu bar, bridge and relay versions; **Pair** shows a code with its real expiry |

**Security spot checks** (once):
- `curl https://relay.<domain>/v1/agents` without a token → `401`.
- `curl "https://relay.<domain>/v1/agents?token=<device>"` → `401` (the query token is ignored).
- Forged `X-Forwarded-For` headers do not escape the pairing rate limit (row 25).
- The relay port is closed from the internet (`deploy/relay/README.md`, the closed-port check).
- The relay journal (`journalctl -u agent-watch-relay`) contains no tokens, no prompt text and no ntfy topic.
- The bridge log contains no prompt text, only `text_len`.
