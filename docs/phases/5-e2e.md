## Setup

1. Relay deployed (3c). `curl https://relay.<domain>/v1/healthz` returns `{"ok":true}`, and `agent-watch-relay version` on the box shows the deployed commit.
2. Bridge service running: `agent-watch-bridge status` (or the `status` plugin action) shows `relay: connected to relay.<domain>` and `herdr: online`.
3. Watch paired, app installed from the **release** build (`./gradlew :app:installRelease`, or a signed APK), notifications allowed.
4. A **sandbox** workspace `aw-sandbox` with three panes in `/tmp/aw-sandbox`, one each running `claude`, `agy` and `opencode` in default permission mode (see the `capture-fixture` skill).
5. `tail -f ~/Library/Logs/agent-watch-bridge.log` in a separate pane.

**Security spot checks** (once):
- `curl https://relay.<domain>/v1/agents` without a token → `401`.
- `curl "https://relay.<domain>/v1/agents?token=<device>"` → `401` (the query token is ignored).
- Forged `X-Forwarded-For` headers do not escape the pairing rate limit (row 25): the relay reads them only from `AW_TRUSTED_PROXIES`.
- The relay port is closed from the internet (`deploy/relay/README.md`, step 5).
- The relay journal (`journalctl -u agent-watch-relay`) contains no tokens, no prompt text and no ntfy topic.
- The bridge log contains no prompt text, only `text_len`.

## Docs to rewrite

**`README.md`** (English, for a new reader):
1. What it is (one paragraph) and a screenshot or GIF from the Pixel Watch 2.
2. The architecture diagram (from the plan §2).
3. Requirements:
   - herdr ≥ 0.9;
   - a VPS behind a TLS reverse proxy (Cloudflare optional);
   - a Wear OS watch (primary) or an Apple Watch (best-effort).
4. Setup in order: relay (link to 3c) → bridge (`configure`, `start`, `pair`) → watch app (install, pair).
5. Supported agents: claude, agy, opencode first-class; others via the generic adapter.
6. Security model (short): outbound-only Mac, hashed device tokens, no raw keys.
7. Troubleshooting: `status` action, log paths, the "herdr stopped" vs "Mac offline" meaning.
