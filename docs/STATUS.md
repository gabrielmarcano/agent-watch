# Status

The one place for the project's state: what is done, what is open, what comes next. Other docs link here instead of restating it. History (how each phase went, fixes, deploys) lives in git: `git log -- <path>`.

**Workflow for agents:** before starting a phase, put your name and the date in its **Claimed by** cell and commit that change alone; do the same under **Open items** for other work that spans several commits or sessions (add the item if it is missing). A fix that fits in one commit needs no claim of its own: update **Open items** in that same commit. When you finish, set its state, remove the items you closed from **Open items**, and add what you could not do. **Then delete the phase's guide:** anything in it still worth knowing moves first to its home (`AGENTS.md` §0), and the rest stays in git history.

### Phone UI and UX
The owner's focus now: the phone's design and usability, based on the messaging apps people already use (WhatsApp first), on the owner's Pixel 8 Pro with the latest Android. The redesign and its slices are written up in [`docs/phases/7-android-ux.md`](phases/7-android-ux.md); the open question is the owner's own list of what feels wrong on the device. The loop is short: change the code, run the `:mobile` JVM tests and lint, `deploy/relay/publish-android.sh --phone` (the release key is in place, so the phone updates itself), and check the change on the phone through the update card. One change at a time, each one visible on the device before the next.
- **Slice 1 (toolchain, `0.4.2`):** the phone compiles against Android 17 (API 37) and targets 36, so it draws behind the system bars; the Compose BOM moved to 2026.03.00 (Material 3 1.4.0) and the Material icons to their own artifact. The watch module is untouched.
- **Slice 2 (theme, `0.4.3`):** the phone has its own light and dark palette, follows the system's light/dark setting and uses the system palette (dynamic colour) by default; the status colours stay ours, in a light and a dark variant. The Settings screen (slice 7) adds the switches for dynamic colour and light/dark. The Material 3 *expressive* motion scheme is still internal in Material 3 1.4.0: it comes with the AGP 9 / Compose 1.12 change, which is its own slice because the watch shares the Gradle root.
- **Slice 3 (chats, `0.4.4`):** a search field over the chats, one filter row (`All · Needs you · Working · Done`, the count on "Needs you") with the machine in a single chip, most-recent-first (the "Needs you" section is gone), an unread **count** badge instead of a dot, pull-to-refresh, a swipe to the right that marks a chat read (the row springs back), a FAB for a new session, and empty states that offer one. The long-press selection mode and muting wait for the notifications slice.
- **Slice 20 (`0.5.10`):** WhatsApp `2.26` screenshot-matched refinements and tactile haptics (`MobileHaptics` + `Modifier.pressScale`): horizontal tinted pill (`56 × 30 dp`, `primaryContainer`) on the active bottom-bar tab with bold selected labels, stadium filter pills (`RoundedCornerShape(50)`, inline count `"Needs you N"` without a middle dot), primary-colored title in light mode and neutral in dark mode, sleek `48 dp` search pill, inline timestamp + double-tick on short 1-line outgoing bubbles, tighter back+avatar unit in the chat top bar, spring-based physical press squish on buttons/chips/tabs/send/approvals, and hardware-tuned haptics (`CLOCK_TICK`, `KEYBOARD_TAP`, `CONFIRM`, `REJECT`, `GESTURE_THRESHOLD_ACTIVATE` when swipe-to-read crosses its threshold).
- **Slice 19 (`0.5.9`):** WhatsApp's chat list, navigation and settings details: divider-free chat rows with bold unread previews, a sent-tick prefix on optimistic outgoing previews, pin/mute icons tucked next to the unread badge on the second line, avatar tap opening the chat sheet, a dynamic floating bottom bar that shrinks into a compact pill on scroll down, a dot on the Settings tab when an app update is ready, and grouped surface cards in Settings.
- **Slice 18 (`0.5.8`):** the conversation feels like WhatsApp's 2026 chat screen: tail-free 18 dp bubbles, a primary double-tick with the time on processed user prompts and a single tick on optimistic pending messages, a floating composer pill with no heavy bottom bar container, fenced code blocks that scroll horizontally with a one-tap **Copy** header, a richer approval card (status dot, warning border, scrollable monospace detail, tonal question buttons), a centered context pill at the top of the conversation, and an unread-turn count badge on the scroll-to-bottom chevron.
- **Slice 17 (`0.5.7`):** the view follows the newest turn unless the owner scrolled up with their own finger (the app's scrolls and the history arriving are not theirs), so the chat opens at the newest message in every case; the keyboard leaves no gap between the field and the keys, and its enter key is a newline (the send button sends). - **Slice 16 (`0.5.6`):** the chat opens at the newest message, for good: the jump to the end waits for the turns (they arrive after the screen does) and the turns stay in the order they happened, so a new one is appended at the end instead of prepended (a prepended turn threw the view into the middle of the conversation).

### Plugin install, tested end to end (2026-10-07)
